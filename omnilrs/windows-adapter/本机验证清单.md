# 接上本机后再验证

下面每一项都还没在这台 Windows 上做过。某一项通过，只说明那一项，不能写成 OmniLRS 已经完全复现。

在 `cmd.exe` 里，仓库根目录为当前目录。Isaac 路径如果不是 `C:\isaacsim`，先 `set ISAAC_PYTHON=你的\python.bat`。

## 0. 解释器是不是 6.2 自带的

```bat
C:\isaacsim\python.bat -c "import sys; print(sys.version); print(sys.executable)"
```

官方栈是 Python 3.12。把打印出来的版本记下来。本文不预设这台机器已经核对过。

同时看一下驱动，只记录 `nvidia-smi` 的输出。不要把别的机器上的 595.58 或 595.99 抄成这台机器的驱动。官方那两个号来自 Linux 迁移记录，见调研报告。

## 1. 子模块和 LFS

```bat
git submodule update --init --recursive
cd omnilrs\upstream
git rev-parse HEAD
git lfs install
git lfs pull
```

`HEAD` 应为 `916b0dc29dc62e51fc18df072db8c73c3173b6c7`。`WorldBuilders` 应为 `c68be6782356f9c51b5c7c70edcffa83d8126b3e`。

抽查三个文件的开头，它们不应再是 `version https://git-lfs.github.com/spec/`：

- `assets\USD_Assets\environments\Lunalab.usd`
- `assets\Ephemeris\de421.bsp`
- `assets\Textures\LunarRegolith8k\LunarRegolith8k_diff.png`

`assets\Textures\LunarRegolithInfinite.mdl` 即使不拉 LFS 也应该是以 `mdl 1.8;` 开头的文本。

## 2. 依赖导入

```bat
C:\isaacsim\python.bat -m pip install -r omnilrs\windows-adapter\requirements-windows.txt
omnilrs\windows-adapter\run_lunalab.bat --check-imports
```

先看失败名单，再决定要不要装 numba / zfpy / GDAL。视觉草稿不依赖后三个。GDAL 的风险写在 `requirements-windows.txt`。

核对 numpy 仍是 2.3.1、scipy 仍是工作站自带的版本。如果 pip 把它们换掉了，先恢复，再继续。

## 3. Lunalab 能否启动

```bat
omnilrs\windows-adapter\run_lunalab.bat --no-robot
```

通过的标准只是：Isaac 窗口打开，实验室 USD 和地形网格出现，进程不是在 import 阶段退出。

然后再去掉 `--no-robot`，看 `nograph_husky.usd` 能不能放进场景。若 OmniGraph 或相机 prim 报错，先留着 `--no-robot` 的结果，不要改上游来“修到能过”。

## 4. 材质和阴影

在已经打开的 Lunalab 里看月壤是否还是纯色或缺贴图。缺贴图时先确认第 1 步的 PNG 已经不是 LFS 指针。

阴影只做目视。issue #140 是 Isaac 6.0 上 Motion BVH 导致阴影和岩石异常，2026-11-10 由报告者关闭，对方称更新 Isaac 后不再出现；另一位维护者说自己在 6.2 上没能复现。这是已知并已关闭的风险，不是这台 Windows 已经复现或已经排除的结论。

## 5. Lunaryard 星历光照

```bat
omnilrs\windows-adapter\run_lunaryard.bat --no-robot
```

`lunaryard_20m` 的恒星引擎会读星历，并按纬度 46.8、经度 -26.3、起始时间 2024-05-21 05:01 放太阳。窗口里应能看到太阳光，而不是只有场景默认灯。这一步依赖 skyfield 和四份星历文件。

出生点若用了默认的 `robot=husky`，是 `[5, 5, 0.1]`，不是环境 yaml 的 `[10, 10, 0.5]`。

## 6. ROS 2 怎么处理

这一轮不要在 Windows 上把 ROS 2 当成必须打通的项。官方激活脚本、库路径和外部示例都是 Linux / Jazzy 或仍停留在 Humble。

二选一，并写进自己的笔记：

- 放弃在这台 Windows 上跑 ROS 2、Yamcs、LargeScale，只保留上面的视觉草稿
- 改到 Ubuntu 24.04，或一块 GPU 能可靠直通的 WSL2，按上游 README 用 pixi，而不是按 Wiki 去建已经删除的 `omnilrs.docker`

不要把 `run.py` 不带参数直接丢给 `python.bat` 当作视觉测试。那样会进默认的 ROS2 模式。
