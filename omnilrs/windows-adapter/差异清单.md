# 上游相对 Windows + `C:\isaacsim\python.bat` 的差异

只列在锁定提交 `916b0dc29dc62e51fc18df072db8c73c3173b6c7` 里读到的内容。适配放在本目录，不改 submodule。

## 安装与平台

| 位置 | 读到的内容 | Windows 上要改的点 |
| --- | --- | --- |
| `pixi.toml` `[workspace].platforms` | 只有 `linux-64`，`glibc = "2.35"` | 没有 `win-64`。`pixi install` / `pixi run` 不是这条 Windows 路径 |
| `pixi.toml` `feature.isaac.pypi-dependencies` | `isaacsim==6.2.0.0`，extras `all` + `extscache` | pixi 会自己装一份 Linux wheel，不会使用 `C:\isaacsim` |
| `pixi.toml` `feature.core.dependencies` | conda-forge 的 `gdal`、`libgdal`、`libglu`、`libstdcxx-ng>=13` | 这些是 Linux/conda 包。工作站 Python 没有这条环境 |
| `pixi.toml` `feature.core.activation.env` | `LD_LIBRARY_PATH=$CONDA_PREFIX/lib:...` | Windows 不用这条变量。Isaac 的 DLL 由 `python.bat` 自己准备 |
| `pixi.toml` `feature.ros2.activation.scripts` | `scripts/activate_isaac_ros.sh` | bash 脚本，路径指向 pixi 环境里的 `isaacsim/exts/isaacsim.ros2.core/${ROS_DISTRO}/lib` |
| `README.md` 安装节 | Linux x86_64、glibc ≥ 2.35、Ubuntu 24.04、驱动 ≥ 580 | 没有 Windows 安装步骤 |
| `scripts/install_native.sh` | `sudo apt` 装 GDAL，然后调用 `~/.local/share/ov/pkg/isaac_sim-2023.1.1/python.sh` | 仍是 2023.1.1 的 `python.sh`。迁移文档 §8.1 也写了它还指向 Isaac Sim 2023。不能拿来装 6.2 |
| `scripts/install_docker.sh` | bash，转去下 DEM 和星历 | 名字像 Docker 安装，内容不是 Windows 启动器 |
| `omnilrs.docker/` | 目录已经不在这个提交里 | 用户向 Docker 镜像已删除。Wiki 还在引用它 |

## 启动

| 位置 | 读到的内容 | Windows 上要改的点 |
| --- | --- | --- |
| `run.py` | `@hydra.main(config_name="config", config_path="cfg")`，然后 `startSim` | 要用 `python.bat` 跑，工作目录必须是上游根目录。相对路径 `assets/...` 和 `RobotParameters` 里的 `os.path.join(os.getcwd(), usd_path)` 都依赖这个 cwd |
| `cfg/config.yaml` | 默认 `environment: lunalab`、`mode: ROS2`、`rendering: ray_tracing` | 直接跑 `run.py` 会进 ROS 2，不是只看场景 |
| `src/environments_wrappers/__init__.py` `startSim` | `mode == ROS2` 时 `enable_ros2` 并 `rclpy.init()` | 没有第四个「无传输」分支。Yamcs 会等 Yamcs 服务器，Zenoh 会起 Zenoh，SDG 会跑标注采集 |
| `cfg/mode/ROS2.yaml` | `bridge_name: jazzy` | 与 `ROS_DISTRO` 必须一致，否则 `enable_ros2()` 抛错 |
| `src/environments_wrappers/ros2/__init__.py` | 启用 `isaacsim.ros2.bridge`，读 `ROS_DISTRO` | 官方库路径按 Linux pixi 环境写。工作站版 `python.bat` 有没有 Windows 版 Jazzy bridge，本文没有验证 |
| `cfg/rendering/ray_tracing.yaml` | `renderer: RealTimePathTracing`，`headless: False`，`multi_gpu: True`，`active_gpu: null` | 草稿原样把这份配置交给 `SimulationApp`。单 GPU 机器上 `multi_gpu=true` 可能不合适，要用覆盖参数自己关 |
| `scripts/activate_isaac_ros.sh` | `#!/usr/bin/env bash`，改 `LD_LIBRARY_PATH` | `cmd.exe` 不会执行它。不要指望 `python.bat` 会 source 它 |

## 场景与资产路径

| 位置 | 读到的内容 | Windows 上要改的点 |
| --- | --- | --- |
| `src/environments/lunalab.py` | `get_assets_path() + "/USD_Assets/environments/Lunalab.usd"` | 字符串拼接，分隔符在 Windows 上通常仍能被 USD 打开，但文件本身是 LFS。指针文件打不开 |
| `src/environments/lunaryard.py` | 加载 `assets/Textures/*.mdl`，并启用恒星引擎 | `.mdl` 已是普通 git 文本。它们引用的 PNG 仍是 LFS。星历在 `assets/Ephemeris/`，也是 LFS |
| `src/stellar/stellar_engine.py` | `skyfield` 读 `de421.bsp`、`moon_080317.tf`、`pck00008.tpc`、`moon_pa_de421_1900-2050.bpc` | 不 `git lfs pull` 的话，Lunaryard 在配置校验阶段就会因文件不存在或不是真星历而失败 |
| `src/configurations/stellar_engine_confs.py` | `__post_init__` 用 `os.path.exists` 检查星历 | 同上 |
| `cfg/environment/lunalab.yaml` | 机器人 `usd_path: assets/USD_Assets/robots/ros2_husky_PhysX_vlp16.usd` | 资源名和内容都是 ROS 2 图。草稿默认改走 `robot=husky` 的 `nograph_husky.usd` |
| `cfg/robot/husky.yaml` | `nograph_husky.usd`，出生点 `[5.0, 5.0, 0.1]` | 这是 Lunalab 注释下的点。Lunaryard 官方环境 yaml 是 `[10.0, 10.0, 0.5]` |
| `src/terrain_management/terrain_manager.py` | 模块级 `import warp as wp` | Lunalab 一加载地形就需要 `warp`。Isaac 6.2 带的是 1.17.0。不要另装一个主版本 |
| `src/terrain_management/terrain_generation.py` | 模块级 `import cv2`、`matplotlib`、`scipy`，并 import `deformation_engine` | 即使变形开关是 `enable: False`，import 链仍然要这些包 |
| `src/terrain_management/deformation_engine.py` | 模块级 `matplotlib`。实现是 numpy，不是 PhysX 软体 | 官方没有 Windows 变形路径。草稿循环不调用 `deform_terrain()` |
| `assets/Terrains/Lunalab/*/dem.npy` | Git LFS | `np.load` 不能读 LFS 指针 |
| `assets/Terrains/crater_spline_profiles.pkl` | Git LFS，且用 SciPy 1.17 重新 pickle | 低于 SciPy 1.17 解不开。迁移文档写明 5.x 环境不能读这份新文件 |
| `assets/Terrains/Lunaryard/` | 只有 `.keepme`，没有 DEM | Lunaryard 地形是程序生成的，不依赖 SouthPole DEM |
| `assets/Terrains/SouthPole/` | 被 `.gitignore` 忽略 | LargeScale 要另外 `aws s3 sync`。脚本是 bash |

## Shell、GDAL、ROS、任务控制

| 位置 | 读到的内容 | Windows 上要改的点 |
| --- | --- | --- |
| `scripts/*.sh` | 全部是 bash：`wget`、`xargs`、`gdalinfo`、`sudo apt` | 没有对应的 `.bat`。在 cmd 里不能直接跑 |
| `scripts/get_dems.sh` / `extract_dems.sh` | 下载 GeoTIFF 再转成 `assets/Terrains/SouthPole` | 转换依赖 GDAL 命令行和 Python 绑定 |
| `scripts/preprocess_dem.py` | `from osgeo import gdal` | `src/` 运行路径不 import GDAL。Windows 上 pip 装 GDAL 容易和 numpy 2.3.1 冲突 |
| `scripts/get_ephemeris_data.sh` | 用 wget 从 NAIF 下星历，作为 LFS 之外的另一条来源 | 需要 bash/wget，或改成手动下载到同名路径 |
| `pixi.toml` 任务 `ros2` | `python run.py mode=ROS2` | 依赖 Jazzy。外部节点官方也要求 Jazzy |
| `pixi.toml` 任务 `yamcs` | `mode=Yamcs environment=lunaryard_40m_workshop robot=pragyaan controller=pragyaan-controller` | 启动前会连 Yamcs。另要 Java 与 `yamcs-mission-control-pragyaan` |
| `pixi.toml` 任务 `yamcs-largescale` | `environment=largescale_workshop` | 还要 SouthPole DEM、warp、numba、zfpy |
| `spaceros_demo.docker/Dockerfile` | `FROM osrf/space-ros:humble-2024.10.0` | 仍是 Humble，README 写明未迁到 Isaac 6.2 |
| `src/environments_wrappers/ros2/simulation_manager_ros2.py` | 循环条件含 `rclpy.ok()` | 把这份管理器原样搬到没有 ROS 的进程里会在 import 时失败 |

## 草稿选择了哪条改法

不在 submodule 里加 `mode=Visual`。`visual_preview.py` 复用 Hydra 配置、`Simulation`、`LunalabController` / `LunaryardController` 和 `RobotManager`，模式枚举用 `SimulatorMode.SDG`，只为了让 `Robot.is_ROS2` 为假，从而不写 ROS domain。它不进入 SDG 采集循环。

`run_lunalab.bat` 和 `run_lunaryard.bat` 负责把 `C:\isaacsim\python.bat` 指到这个脚本，并允许 `ISAAC_PYTHON` 覆盖路径。
